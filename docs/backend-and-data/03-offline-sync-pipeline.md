# The Offline Synchronization Pipeline

Merian's core differentiator is treating Off-grid nature encounters as a first-class citizen using native Apple offline architecture.

## How the Queue Works

The `OfflineQueueManager` handles the persistence explicitly with no risk.

1. **Inference Failure & Queueing (`OfflineQueueManager.shared.enqueueCapture`)**
   When a hiker takes a picture miles away from a cell tower, the UI passes the raw capture and active telemetry context (like `gpsLatitude`, `gpsElevation`, `weatherCondition`, `weatherTemperatureF`, `relativeHumidity`, `uvIndex`, `cameraPitchDegrees`, `compassHeading`, `subjectDistanceInMeters`, `locationName`, and `isFlashFired`) to the `InferenceEngine`. To strictly protect this hardware data from premature UI deallocations across asynchronous boundaries, variables like `isFlashFired` and `subjectDistanceInMeters` are actively extracted into structural copies prior to explicitly setting the `imageToCrop` sheet to `nil`. When pushed to the queue, all constraints gracefully drop into the `OfflineQueuedScan` SwiftData model. Upon reconnection, the system strictly parses the `subjectDistanceInMeters` offline float back into the stringified `depthScaleText` (e.g. `1.5 meters`) perfectly preserving LiDAR bounds. To entirely prevent application storage block bloat on long off-grid excursions, the engine inherently detaches a compression loop mapping the 12MP buffer down into a highly compressed JPEG natively before any networking attempt. 
   **The Circuit Breaker (`CircuitBreakerManager`)**: To protect the UI from hanging permanently on degraded 3G networks or backend outages, the inference loop routes through `CircuitBreakerManager`. If subsequent HTTP errors or timeouts threshold limits natively, the circuit "trips". Any active tripped state instantly forces all new camera captures dynamically straight to the offline queue immediately, completely bypassing useless network connections to guarantee a 0-latency shutter experience.
   
   If `InferenceEngine` subsequentally encounters a `URLError` or network timeout natively interacting with the backend, it securely catches the failure. **Critically, the Offline Queue is strictly a Merian Pro feature**. Inside the catch block, the engine verifies `RevenueCatManager.shared.isProActive`. If the user is on the free tier, the engine throws `APIError.proRequiredForOfflineTracking`, refunds their scan token organically, and fires a `TriggerPaywall` notification (which `CameraViewModel` catches instantly to display the paywall). If they are Pro, it delegates the newly constrained payload instantly to `OfflineQueueManager.shared.enqueueCapture` (which now correctly binds `subjectDistanceInMeters`, `cameraPitchDegrees`, `compassHeading`, and `uvIndex` exactly from the failure point). Structurally isolating this step securely, `.enqueueCapture` spawns a `Task.detached(priority: .userInitiated)` explicitly throwing the ~300KB NVMe `Data.write` physical disk commit permanently off the UI `@MainActor` thread. This mathematically avoids Main Thread file I/O locks natively, completely preventing the camera viewfinder from stuttering during capture. Once the physical bytes safely clear hardware cache validations natively into the iOS `URL.documentsDirectory`, an `await MainActor.run` jump back occurs where a new `OfflineQueuedScan` database object is written securely into the physical `.modelContainer()` using Apple `SwiftData`. Furthermore, if the user explicitly pushes the app into the background during a mid-flight active inference, `AppDIContainer.handleBackgroundPhase` explicitly intercepts the native `.background` cycle, rigidly verifying `revenueCatManager.isProActive` once more, and rescues the payload. Critically, to prevent the 12MP uncompressed capture from leaking onto the user's hard drive, the AppDelegate boundary prioritizes extracting the `inferenceEngine.activeCompressedPayload` (the ~300KB downsampled footprint) first, completely protecting device storage. It explicitly reads the active sensory context layers directly off the `InferenceEngine` state (`activeDistanceInMeters`, `activeLocationName`, etc.) to securely pass every parameter directly down into `.enqueueCapture` to ensure background-rescued scans preserve their complete physical dataset (orientations, weather, distances, logic) mapping perfectly offline before suspending the app layer.

2. **Network Awakening (`NWPathMonitor`)**
   The `NWPathMonitor` instance listens natively to the internal cellular stack continuously. When a connection flips `.satisfied`, the manager debounces for 1,000 milliseconds to guarantee the pipeline has completely stabilized without thrashing before starting processing.

3. **Background Processing & Payload Compression (`URLSessionConfiguration.background`)**
   The manager checks that the queue isn't already syncing and securely verifies `!HardwareOrchestrator.shared.isExpeditionModeActive` to inherently prevent background cellular battery drain on low-power devices. It then natively engages `SyncStateManager.shared.beginSync(itemCount:)` securely broadcasting the exact integer volume of pending payloads directly to the global `@MainActor` without crashing. This explicitly powers any passive UI indicators (like spinning cloud icons in the Scans library) cleanly mapping state without locking up the upload.
   It then bounds an explicitly constrained `FetchDescriptor` query with `descriptor.fetchLimit = 5` to chunk processing limits safely preventing edge timeout limits. Critically, before processing the payload, the manager queries `backgroundSession.allTasks`, explicitly filtering out `PendingScanPayload` items that are currently mid-flight inside the background queue. This physically stops the application from blasting duplicate upload constraints via `generate-upload-urls` if the user drops cell service and immediately regains it. It generates raw Presigned URLs from `/generate-upload-urls`.

   Critically, the core payload loop is securely initialized explicitly within a `Task.detached(priority: .background)` block, completely escaping the singleton's `@MainActor` confinement. Inside the detached task, a precise `@ModelActor BackgroundDatabaseActor` strictly intercepts the `modelContext.fetch` generation natively decoupling the heavy SwiftData persistent fetch entirely from the main thread. It explicitly maps the data natively into purely standard thread-safe Tuple matrices (`PendingScanPayload: Sendable` lightweight structs) eliminating all `EXC_BAD_ACCESS` data race execution crashes and UI freezes. Inside this detached thread, the exact constrained `1:1` `~140KB` geometric payload successfully generated initially by `ImageCropperView` is natively loaded straight from `URL.documentsDirectory` efficiently. It safely skips secondary memory-heavy downsampling operations because the payload logic is inherently resolved at crop time seamlessly! Strict care was taken during crop generation to guarantee thread safety: while memory limits are securely crunched out via raw `cgImage.cropping` inside detached `autoreleasepool` thresholds, the final `UIGraphicsImageRenderer` render pass explicitly forces evaluation back out onto an `await MainActor.run` jump, completely destroying unsafe UIKit background thread crashes globally. State interactions are cleanly routed back via safe `await MainActor.run` enclosures.
   This pre-compressed payload is safely cached into a temporary `URL.cachesDirectory` file identified exactly by its unique `scanId` to strictly decouple and prevent asynchronous overwrite crashes natively. Prior to physically caching the active payload out to a temporary directory in preparation for Cloudflare R2 bounds, the system aggressively verifies disk boundaries utilizing `.fileExists(atPath:)`. If a user implicitly swept their local library natively during a multi-day off-grid excursion (wiping the reference `.jpg` bytes cleanly before the pipeline synced), building an active URLSession upload task physically over a non-existent file forces an instantaneous failure loop draining battery capacity indefinitely. By expressly checking physical bytes and natively forcing a `.softDeleteQueuedScan` tombstone to jump out, dead `scanId` variants efficiently skip iteration breaking the infinite retry bounds entirely. It is then cleanly handed directly into a strictly isolated native iOS `URLSession` Background Queue natively. The Operating System assumes full responsibility for byte transmission, massively accelerating upload times over spotty 3G cellular boundaries.
   _Note: A strict `UIBackgroundTaskIdentifier` map requests up to 30 seconds of explicit background execution time from iOS. An `expirationHandler` is wrapped locally around the presigned URL generation phase to immediately stop the queue loop, leaving remaining items safely in SwiftData without corrupting data if the OS randomly runs out of time on weak 3G connections. Crucially, it implements an expirationHandler closure to safely suspend the loop and call endBackgroundTask if the OS runs out of execution time, preventing data corruption and app crashes. To satisfy strict Swift 6 Data-Race concurrency constraints explicitly avoiding 0x8badf00d OS Watchdog terminations, the `UIBackgroundTaskIdentifier` bounds are safely wrapped within an `@unchecked Sendable` Swift Box (using a `final class` reference semantic) guaranteeing that the execution block accurately executes `UIApplication.shared.endBackgroundTask()` explicitly avoiding an invalid mutation fault or loop runaway natively._
4. **Upload Lifecycle via URLSession Delegates (iOS Background Hooks)**
   - **Step A:** iOS natively transmits the data into the Staging bucket.
   - **Step B:** Once bytes finish landing securely, SwiftUI invokes the `@UIApplicationDelegateAdaptor` inside `AppDelegate`, transferring the `handleEventsForBackgroundURLSession` handler straight to `OfflineQueueManager`.
   - **Step C:** Native constraints fire `.urlSession(_:task:didCompleteWithError:)` triggering locally. The queue manager explicitly checks the HTTP status boundary. If a user has been off-grid longer than 24 hours causing their Cloudflare R2 presigned URL to expire (yielding a `403 Forbidden`), or if transient backend service errors occur (`500`, `502`, `503`, `504`), the manager strictly prevents soft-deleting the payload. It cleanly sweeps the `tempFileURL` buffer natively while preserving the `OfflineQueuedScan` safely within SwiftData, guaranteeing a fresh URL generation safely triggers on the next `.satisfied` network cycle. If completely successful (HTTP `200`), the queue manager explicitly fetches the uploaded file via edge bounds (`MerianNetworkClient.shared.analyzeSubject`), retrieving the fully resolved JSON inference payload securely.
   - **Step D:** The returned taxonomy is passed securely to a dedicated `BackgroundDatabaseActor` where it decodes the payload, executes a strict `FileManager.default.moveItem()` hook migrating the offline image boundaries exclusively preventing sandbox destruction natively entirely off the Main Thread. It then safely persists the fully identified creature explicitly into the user's `SwiftData` Scans. Finally, `processAndCleanupOfflineScan(scanId:)` automatically cleans up the old explicit queue references purely on its own background thread, completely insulating the 60FPS UI from stuttering during batch updates.

## Deletions in Offline Environments

Scan permanence and user privacy dictates that explicitly deleted datasets are permanently erased. Merian ensures these erasures map natively even fully offline:

1. **Optimistic Destruction (`ScanRepository.eradicateScan`)**
   When a user destroys a scan natively via the `.contextMenu`, the underlying filesystem `FileManager` aggressively detaches the image cache bytes off the physical disk payload immediately mapping a strict 0-byte destruction locally. 
2. **Cloud Deletion Tasking (`PendingCloudDeletionTask`)**
   To bypass connectivity dropping randomly during erasures, SwiftData natively persists a schema-scaled `@Model final class PendingCloudDeletionTask` which queues up the raw `scanId` locally safely bounding the target. The UI aggressively executes `.delete` physically dropping the UX bounding out of sight instantly for the user, executing a fully synchronous optimistic UI drop.
3. **Deletion Interception (`softDeleteQueuedScan`)**
   If the scan being destroyed is actively queueing for its native initial upload stream inside the offline boundary natively, `OfflineQueueManager.shared.softDeleteQueuedScan` explicitly intercepts the background worker terminating the native upload path bounding permanently isolating upload destruction cleanly.
4. **Network Polling Sync (`syncPendingDeletions`)**
   As `NWPathMonitor` wakes the application on cellular bounds mapping, it explicitly runs `syncPendingDeletions()` triggering backend Cloudflare R2 object erasures alongside PostgreSQL tuple obliterations securely executing via a mapped JWT `MerianNetworkClient.shared.deleteScan()` edge payload. The SwiftData queue cleans up the tasks natively inside the `.background` task context mapping.

## Restoring Historical Workloads (Rehydration)

To securely support multi-device logic and app reinstalls, Merian implements a physical boundary bypassing standard fetch drops: 

1. **The Rehydration Native Sync (`syncHistoricalScansDown`)**
   Explicitly embedded in `ScanRepository.shared`, this robust task queries the Supabase Edge natively pulling a joined `scans` + `species_dictionary` PostgreSQL JSON response. It sequentially filters all UUIDs securely querying the edge payloads perfectly bounded inside a `.eq("user_id", value: userId)` isolation parameter before mapping them internally inside `SwiftData`, robustly isolating the user's private global payload history explicitly away from cross-tenant data leaks natively.
2. **Lifecycle Execution Hook**
   This synchronization executes aggressively the pure second a user completely transitions from `Ghost` -> `Authed` inside the `SupabaseManager.setupAuthStateListener` or uniquely whenever the app recovers foreground capabilities out of deep bounds (`AppDIContainer.handleActivePhase`).
3. **Ghost-Rendering Image Optimization**
   To entirely avoid destroying device cellular data limits downloading massive multi-gigabyte historical image files physically into iOS, the hydration engine smartly forces the SwiftData payload `.localImagePath = nil` while simultaneously overriding `.referenceImageUrl` to dynamically hold the specific historical Cloudflare R2 URL natively sourced directly out of PostgreSQL. Because the `scans.image_storage_urls` array exclusively stores public Cloudflare Web bindings (`https://media.merian.app/...`) instead of legacy S3 API strings (`.cloudflarestorage.com`), iOS clients can physically trigger `URLSession` native fetches natively bypassing all `HTTP 400 Bad Request` or `HTTP 403 Forbidden` authorization lockouts automatically. This explicitly routes all native frontend components (`ScansThumbnailView` and `InsightSheetView`) into utilizing Apple's asynchronous cache layers securely downloading exactly what the UI needs right exactly when the user views it.

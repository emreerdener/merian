# Feature Modules and UI Architecture

Merian's UI architecture strictly adheres to a modular, glassmorphic design philosophy, ensuring maximum reuse of Swift components while safely decoupling heavy data operations from the main rendering loop to maintain a continuous 60fps framerate.

## 1. Onboarding & Permission Priming (`OnboardingView`)

To satisfy Apple's strict privacy guidelines and secure high opt-in rates without creating friction, Merian entirely intercepts the cold boot via a programmatic **Permission Priming** sequence. The `Onboarding` feature vigorously adheres to the Domain-Driven folder architecture. The structural state map (`Models/OnboardingStep`) and iOS hardware delegates (`Utilities/LocationPermissionDelegate`) are rigorously decoupled natively from the main UI orchestrator (`Views/OnboardingView`). Each fallback step is natively instantiated inside completely discrete SwiftUI bounds within `Components/` to prevent monolithic view bloat.

- **Enum-Backed State Machine (`OnboardingStep`)**: Radically enforces sequential permission gating (`.welcome`, `.camera`, `.location`, `.photoLibrary`, `.ready`) via a strict `switch` statement overlaying a `ZStack`. This completely prevents users from accidentally bypassing the `AVCaptureDevice` execution prompt by simply swiping (a core flaw of standard `.tabViewStyle(.page)` paradigms).
- **Asymmetric Glassmorphism Integrations**: View state transitions are globally synchronized strictly using `withAnimation(.spring(...))` pushing fluid `.asymmetric(insertion: .move, removal: .move)` structures.
- **DRY Layout Abstraction (`BaseOnboardingStepView`)**: To eliminate SwiftUI boilerplate, all individual steps (`WelcomeStepView`, `CameraPermissionStepView`, `LocationPermissionStepView`, etc.) explicitly inherit their structural geometric bounds and native encapsulated `Rive` shapes exclusively from a generic, highly reusable `BaseOnboardingStepView`. This rigidly protects UI consistency while supporting trailing optional button matrices (such as "Skip for now").
- **Hardware Fallbacks**: 
  - `CameraPermissionStepView`: Asynchronously wraps `AVCaptureDevice.requestAccess(for: .video)` closures directly into the UI state, allowing the system to naturally slide onto the Location view exactly when the iOS permission boundary resolves.
  - `LocationPermissionStepView`: Hooks heavily into a clean `CLLocationManagerDelegate` observing dynamic authorization loops. Crucially, it provides a transparent "Skip for now" fallback button explicitly preserving Apple's App Store Review requirements without alienating free users.
- **Root View Handoff (`MerianApp`)**: Driven explicitly by an `@AppStorage("hasCompletedOnboarding")` physical boundary. The moment the user completes Step 4, SwiftUI dynamically rewires the physical WindowGroup, unmounting `OnboardingView` forever and instantly mapping heavy hardware layers back to the `CameraRootView`. Because `CameraRootView` remains entirely uninitialized in RAM until this flag hits `true`, intense background dependencies (like `AVCaptureSession.beginConfiguration`) are elegantly shielded from the onboarding frames natively.

## 2. The Scans Library (`ScansSearchView`, `ScansSearchManager`)
The Scans tab acts as the user's primary offline biological journal. 

### Native Paging Navigation
- **Horizontal Swipe-to-Navigate**: The primary `ScansSearchView` bypasses strict UIKit `UIPageViewController` limits by entirely utilizing a modern iOS 17 pure SwiftUI `ScrollView(.horizontal)` combined with `.scrollTargetBehavior(.paging)`. This strictly binds to `.scrollPosition(id: $activeTab)` enabling a buttery smooth 1:1 interactive swipe between the "Scans" (Library) and "Collections" arrays while explicitly dropping `.containerRelativeFrame(.horizontal)` wrappers without inheriting native `TabView` safe area anomalies natively.
- **Automatic Search Routing**: The UI leverages `.onChange` modifiers for both the search query and the `isSearchFocused` binding. Initiating a search dynamically forces `activeTab = .library` inside a `.withAnimation` block to smoothly transition back from Collections.
- **Persistent Bottom Context**: The bottom-anchored, liquid-glass search bar (hosted natively strictly via `.searchable`) floats elegantly above the `ScrollView` content. By aggressively dumping `.toolbarBackground(.hidden, for: .bottomBar)` and directly stripping the text field's trailing background natively within Swift, the interface explicitly ensures the physical photo grids flow continuously directly beneath the floating bar without bounding-box backgrounds clipping the rendering tree.

### Search & Filtering
- **Native iOS 18 Bottom Search Bar**: Integrates the native iOS 18 `.searchable` and `.searchDictationBehavior(.inline)` modifiers ripped out of the top drawer and dynamically pinned to the bottom placement via `DefaultToolbarItem(kind: .search, placement: .bottomBar)`.
- **Dictation & Clear Mechanics**: Relies strictly on native SwiftUI dictated microphone capabilities and standard 'X' overlays, requiring zero custom `UIViewRepresentable` bindings. Applies `.ultraThinMaterial` toolbars natively matching the aesthetic.
- Driven by `ScansSearchManager`, which utilizes a debounce boundary (`.onChange`) to filter arrays asynchronously without lagging the visual input.
- **Dynamic Filter Bar Eradication & Live Headings**: The UI actively tracks the `isSearchFocused` state via the `.searchable(isPresented:)` binding alongside the `searchManager.searchQuery`. The horizontal sequence binding the filter buttons has been completely abstracted into the highly reusable `CategoryFilterBar.swift` component out of `ScansSearchView.swift`. The component strictly operates on pure Swift `.Binding` layers and explicitly passed string arrays gracefully wrapping native routing closures cleanly out of the monolithic CoreData `ScansSearchManager` constraints organically. The moment a user taps the native iOS search field to bring up the keyboard, the horizontal Category filter pill bar dynamically unmounts. It is instantly replaced natively by a dynamic **"Search library" / "Search results"** contextual header and a live array count tracking the active search, cleanly transitioning state without jarring layout jumps.
- Binds directly to SwiftData's `allRecords` using `@Query(sort: \LocalScanRecord.timestamp, order: .reverse)`. The query explicitly uses a `#Predicate` to filter out non-biological scans (`$0.isBiological == true && $0.commonName != "Unknown Subject"`), keeping the primary library strictly focused on validated nature and completely blocking undetermined edge cases from polluting the feed.
- **Offline Semantic Routing**: Queries filter both explicit user-facing `commonName`/`scientificName` text and invisible `semanticTags` locally embedded by the AI model entirely off-grid (such as 1-3 visually dominant `colors`).
- **LazyVGrid Rendering Resilience**: To prevent fatal SwiftUI rendering engine drops when rapidly swapping multi-thousand item text collections, `ScansSearchManager` strictly enforces explicit `.withAnimation { self.filteredScans = ... }` boundary updates cleanly forcing OS layout calculations natively offline.
- **DRY Scan Matrix (`ScanGridMatrix`)**: To eliminate duplicated layout constants spanning the `ScansSearchView`, `NonBiologicalScansView`, `CollectionDetailView`, and `ScanSelectionSheetView`, the physical 3-column `LazyVGrid` and explicit `Button` action wrappers were fundamentally consolidated into a generic, highly reusable `ScanGridMatrix` component in `Core/UI/Components/`. It securely parses an array of `LocalScanRecord` structures and explicitly relies on an `onDelete` closure and `@ViewBuilder` for seamless context-specific UX boundaries (such as injecting `Remove from collection` action buttons securely) completely agnostic of the underlying global grid.
- **Unified Empty States (`EmptyStateView`)**: Monolithic `VStack` geometries used for 0-result states natively inside `ScansSearchView` and `ScanSelectionSheetView` were entirely purged. They now rigorously inherit the global `EmptyStateView` component mapping to strongly typed dynamic message fallbacks cleanly unifying the missing-data UX natively across the whole library.

### Collections (Top-Level Photo Albums)
- In `MerianSchemaV6`, users can organize `LocalScanRecord` entries into distinct `ScanCollection` buckets.
- Leverages SwiftData `@Relationship` mapping dynamically natively inside a nested 3-column `LazyVGrid`, providing an "Explore Library" modal inside `CollectionDetailView` natively to link IDs safely without duplicating exact 12MP local images.
- Instantly navigates scans from the user's library into explicit folders dynamically, protecting original creation timestamps safely.
- **SaveToCollectionSheetView Eradication**: The standalone `SaveToCollectionSheetView` has been permanently deleted. Collection routing from the `InsightSheetView` is now handled dynamically via a native iOS Menu without pushing opaque sheets.
- **Favorites Isolation**: A default "Favorites" `ScanCollection` is dynamically seeded for every user. Instead of polluting the `.onAppear` blocks synchronously tying up view rendering matrices natively in both `ScansSearchView` and `InsightSheetView`, this bootstrap initialization logic is now fully centralized. It explicitly drops straight into `ScanRepository.shared.configure(with:)` so the database flawlessly seeds the default folder strictly exactly once at startup. Instead of polluting the primary `LazyVGrid` matrix identically to user-created collections, "Favorites" is strictly mathematically filtered out and pinned as a permanent, distinct `NavigationLink` list container immediately above the Non-Biological vault, establishing lightning-fast dedicated access.
- **Collection State Toasts**: Natively binds a localized `.task(id:)` auto-dismissing `toastOverlay` modifier securely anchored to the `InsightSheetView` hierarchy. This explicitly relays haptic synchronization and glassmorphic `.ultraThinMaterial` pill notifications providing physical confirmation when scans are successfully pushed to or popped from specific `ScanCollection` relations.
- **Non-Biological Scans Isolation**: A dedicated list-item navigation button dynamically routes users to a mirror component `NonBiologicalScansView.swift`, which inversely queries exclusively for `$0.isBiological == false || $0.commonName == "Unknown Subject"`. This provides a physical vault for random objects and failed taxonomy inferences without polluting the biological library. Architecturally, this navigation link physically sits at the bottom of the `Collections` tab viewport, intentionally utilizing tightened `.padding(.vertical, 8)` bounds to bridge the vertical gap seamlessly to standard user collections without abandoning focus.

### Main Tab Bar
- **Bottom Position Alignment**: The `Explore`, `Scans`, and `Profile` primary actions are strictly hoisted to a custom floating liquid glass capsule component (`MainTabBar`) overlaid at the bottom of the camera feed.
- **Ultra-Thin Material**: To maintain an immersive glassmorphism experience, the tab bar leverages iOS's native `.ultraThinMaterial` background. This automatically adapts to the visual contrast of whatever the camera is currently looking at natively responding to the environment, paired with a specular border (`.strokeBorder`) gradient and soft drop shadow.
- **Sheet Navigation**: Tapping any navigation element natively spawns `.sheet` structures (`SettingsView`, `UserProfileView`, etc.) that slide completely over the camera interface to strictly prevent any structural re-routing of the global hierarchy or interruptions to the `.isCapturing` hardware constraints.

### Memory Integrity (`ImageDownsampler` & Concurrency)
- Natively guards the iOS lifecycle against "Out of Memory" (OOM) crashes by strictly decoupling explicit `Data` buffer conversions out of SwiftUI into an isolated `ImageDownsampler` static abstraction, leveraging Core Graphics interpolations dropping massive 12MP files seamlessly into RAM sequentially rather than instantiating memory-heavy `UIImage(contentsOfFile:)` chunks across grid loads.
- **Thread Starvation Prevention**: Execution arrays natively hitting Apple's `ImageIO` functions (`CGImageSourceCreateWithURL`) are explicitly moved cleanly into `Task.detached(priority: .userInitiated)` structures. This seamlessly protects the Swift 6 global cooperative thread pool from halting the main UI rendering matrix sequentially.
- **Historical Payload Override**: To entirely avoid destroying device cellular data limits downloading massive multi-gigabyte historical image files physically into iOS, the hydration engine (`ScanRepository.syncHistoricalScansDown`) smartly forces the SwiftData payload `.localImagePath = nil` while simultaneously overriding `.referenceImageUrl` to dynamically hold the specific historical Cloudflare R2 URL. This explicitly routes all native frontend components into utilizing Apple's asynchronous cache layers natively. Specifically, both `ScansThumbnailView` and `AsyncLocalImageView` pipe these paths directly into the thread-safe `LocalImageLoader` actor. If missing from Sandboxed Documents natively, the actor robustly executes a `fetchNetworkFallback` via `URLSession` organically shielding all structural frontend view code from conditional 50-line `if let` blocks completely.
- **Sandbox Resiliency**: Physical disk file references completely drop absolute path trails prior to parsing (via `.lastPathComponent`). This gracefully secures the `LocalImageLoader` payload extracting `Documents/` payload bytes dynamically without rendering broken thumbnails when the OS natively shifts active container mount paths (e.g. during Xcode Simulator rebuilds or iOS firmware updates).

## 3. Inferences & Telemetry (`InsightSheetView`)
The `InsightSheetView` is Merian's central contextual readout, triggered immediately after an Edge API loop or seamlessly opened offline via the Scans library.

### Core Rendering Logic
- **Modular Component Isolation**: The `Insights` feature explicitly defines a localized Domain-Driven folder hierarchy to guarantee maximal compilation times and separation of concerns. Top-level fullscreen layouts (`InsightSheetView`, `DiagnosticComparisonView`) are strictly hoisted into `/Views`. 
  - The massive structural `SwiftUI` `@ViewBuilder` layout blocks previously hardcoded in `InsightSheetView+Layout.swift` were completely decoupled. The Taxonomy Header, Toxicity Banner, Tree, Conservation Card, and Description sections are now fully abstracted into `InsightBiologicalContentView.swift`, while fallback states map structurally into `InsightNonBiologicalContentView.swift`.
  - `DiagnosticComparisonView` specifically renders the AI's flattened array string bullet points dynamically parsing raw trait differentials strictly into scalable `HStack` layouts instead of legacy HTML-style data grids.
  - Structural sub-elements (`InsightCarouselView`, `InsightToxicityBanner`, `BadgeView`) are decoupled identically into `/Components`. Underlying SDK wrappers (like the UIKit `SFSafariViewController` bridge) are extracted into `/Utilities`. This totally eliminates monolithic UI bundles.
- **Adaptive Dark Mode & System Materials**: All hardcoded dark-mode overrides previously limiting the modal have been explicitly eradicated. The sheet maps entirely to Apple's adaptive `.ultraThinMaterial` backgrounds responding natively to the user's system appearance correctly maintaining accessibility contrast bounds dynamically.
- **Safety Critical Block**: `InsightToxicityBanner` parses `speciesData?.insightData.isPoisonous` instantly displaying red alert ribbons above the fold to guarantee hiker safety natively.
- **Ecological Validations & Legacy Hydration**: Binds fallback indicators for "Not biological" or "Not a live capture" gracefully routing edge failure cases into a clean UI without hard-crashing. If an item scores `<85%` confidence, it triggers the `DiagnosticComparisonView`. Additionally, isolated `BadgeView` instances explicitly handle legacy historical payloads seamlessly rendering weather/location geometries safely if the dataset pre-dates the MapKit reverse-geocoding era.
- **Liquid Glass Edge-to-Edge Alignment**: `InsightSheetView` natively strips all `NavigationStack` and structural UIKit toolbars completely, explicitly isolating the layout into a `ZStack` bounding `.ignoresSafeArea(edges: .top)`. The core top navigation logic is dynamically recreated as a custom floating glassmorphic `.ultraThinMaterial` pill block encapsulating the close, share/save, and standard deletion menus, directly overlapping the hero image gracefully without rigid UI frames.
- **Inline Action Buttons & Vertical Taxonomy**: Core data modifiers (Add to Collection, Flag for Review) were natively ripped out of the secondary functional menus and promoted directly below the core description block into massive, full-width `.capsule` gradients for rapid ergonomic execution. The Linnean classification natively abandons legacy horizontal scrolling `.TaxonomyNode` pills entirely, transforming structurally into a sleek, vertical key-value `.glassCard` dictionary explicitly outlining the terminal SPECIES text natively.
- **Scans Contextual Imagery**: When opened directly from the historical Scans library, the system intelligently intercepts the UI routing and physically forces the *user's natively captured local photograph* to dominate the Hero Carousel, rather than defaulting to the Wikipedia/GBIF reference imagery. This builds profound personal connection to the data.
- **Decoupled Asynchronous Validations**: To protect rendering bounds cleanly, all asynchronous `FileManager` fetches structurally identifying historic local payloads are cleanly removed from `InsightCarouselView` and natively isolated into the background threaded `load` pipeline inside `InferenceEngine`.
- **Isolated Animation Engine**: Features a complex, continuously rotating 360-degree `LinearGradient` (rainbow styling) for pending AI states. To guarantee perfect 60fps frame rates without stuttering, the animation logic is rigorously decoupled and strictly bound inside a localized struct/equatable bound, completely isolating it from `CameraViewModel` SwiftUI layout redraw strikes.
- **Visual Virality & Sharing**: Implements a fully native `UIActivityViewController` pipeline explicitly built to stage rich imagery payloads perfectly. When tapped, the system dynamically intercepts the actual photograph (live capture, local disk cache, or safely pulled Cloudflare URL). Crucially, to prevent the main `@MainActor` UI thread from violently stuttering or completely freezing when extracting massive raw 12MP payloads natively via `Data(contentsOf:)` and `UIImage(data:)`, these operations evaluate completely out-of-bounds inside a strict `Task.detached(priority: .userInitiated)`. The pipeline only jumps back natively into the Main Thread to explicitly `presentShareSheet(items:)`. Any local file retrieval dynamically executes an absolute path expansion (`URL.documentsDirectory.appendingPathComponent(path)`) prior to extraction, ensuring iOS Share Sheets actually render the payload map rather than silently dropping abstract local filename strings natively. Additionally, the remote URL parsing actively trims invisible whitespace characters (`.trimmingCharacters(in: .whitespacesAndNewlines)`) previously left behind by legacy array decoders preventing fatal `nil` URL resolutions natively. To prevent the iOS Messages app from aggressively discarding the `UIImage` physical attachment in favor of a "Rich Link Bubble", the `merian.app` Universal Link is explicitly folded directly into the core `String` text message rather than passed as a standalone `URL` object to the iOS Share Sheet natively.
- **Exporting Raw Photography (`Save my photos`)**: Inside the toolbar menu, users can extract their biological captures directly to the iOS Camera Roll universally without triggering the Auto-Save settings. It actively parses `PhotoLibraryManager.saveImageManual(imageData:)` with `.addOnly` permissions natively filtering the `inferenceEngine` remote payload arrays. Like the share sheet, this strictly requires exact `.documentsDirectory` resolution loops across iOS Sandbox security boundaries natively, shielding Wikipedia/GBIF external references from downloading inherently.
- **Optimistic UX (Deletions)**: Users can permanently obliterate local and global data securely via `.contextMenu` bounds (Library, Collections) or the Toolbar `Menu` inside Insight bounds. Instantly bounding a `.destructive` `confirmationDialog`, pressing "Delete" executes an immediate zero-latency removal from the local UI matrix, triggering a heavy `HapticManager.shared.triggerErrorThump()` drop, while securely routing physical R2 bytes and PostgreSQL rows to the `PendingCloudDeletionTask` detached background queue invisibly to not block the UI thread.
### External API Enrichment
- Spawns parallel external lookups fetching the full taxonomic classification into the visual `InsightTaxonomyTree`.
- To ensure the fastest user experience without blocking the initial insight response, the iOS client autonomously fetches Wikipedia data independently. Immediately after the Gemini payload renders the underlying components, `InferenceEngine.asynchronouslyFetchWikipediaAndHydrate` natively pings the Wikimedia REST API (e.g., `/api/rest_v1/page/summary/`). Because `speciesData` relies on unstructured `@Published` bindings natively, when the data resolves on the Swift actor, the Wikipedia abstract paragraph dynamically fades directly into the active `InsightSheetView` organically without mandating modal dismissal limits or UI locks.

## 4. Account (`UserProfileView`)
The primary identity portal bridging local usage limits with the Supabase Ghost Session ecosystem. The legacy `SettingsView` sheet was utterly deprecated natively, migrating all structural toggles, bounds, and permissions directly into `UserProfileView` natively mapped as a perfectly fluid `.InsetGroupedListStyle`. Furthermore, `UserProfileView` was fundamentally stripped of direct logic executing SQLite bounds or `URLSession` mutations natively. Complex side effects (such as fetching DB boundaries seamlessly mapping API payloads) are securely extracted into a dedicated `UserProfileViewModel` natively, structurally rendering `UserProfileView` as a flawless explicit layout hierarchy.

### Native OAuth & Entitlements
- Implements purely native Swift `SignInWithAppleButton` and `GoogleSignInButton` SDK boundaries securely retrieving external `.idTokens`. These buttons are dynamically unmounted and embedded cleanly at the *very top* of the active View directly inside the `UserProfileHeaderView` if the `supabase.isGuestUser` condition resolves, cleanly erasing nested setup friction globally.
- Reassigns initial Anonymous IDFV GoTrue Sessions natively merging user arrays into persistent Cloud records.
- Instantly pulls explicit `RevenueCatManager.shared.isProActive` booleans conditionally hiding or throwing the `PaywallView` dynamically if they hit their daily 3-scan limit. The Profile natively leverages this observed property to dynamically label the user's current subscription tier (e.g. "Merian Pro" or "Free") explicitly inside the Manage Plan row. The `PaywallView` seamlessly inherits physical system color schemes dynamically rendering in stunning Light or Dark mode.
- Renders global gamification statistics including `uniqueSpeciesCount` and `currentStreak` in the stats grid, while evaluating the user's `persona` (Explorer Rank) dynamically purely offline within the profile header. Both the `StatCardView` modules and `UserProfileHeaderView` bypass native list limits completely by deploying geometric `24px` Continuous Squircles driven strictly through `.background(...)` shape modifiers explicitly bounded away from intrinsic OS table cell clipping masks. Instead of blocking the UI on remote PostgreSQL network requests, it utilizes heavily optimized `SwiftData` `@Query` property wrappers mapping array statistics natively preventing UI lag and dropping network errors cleanly for a flawless "Digital Terrarium" profile reflection.

### Aesthetic Customizations
- Contains the `AppIconManager` allowing `Pro` users to natively swap their iOS Springboard Icon using `UIApplication.shared.setAlternateIconName` natively. This natively updates both the app boundary and the underlying `Config.xcconfig` bounds safely without requiring a restart.

### Hardware Preferences
- **Expedition Mode**: Manually throttles the `HardwareOrchestrator` to 24fps and disables intensive visual blurs to preserve battery.
- **Live Viewfinder Hints**: Allows users to manually disable real-time AI scanning hints before capturing to securely reduce thermal loads or minimize battery drain.
- **System Haptics & Camera Roll**: UserDefaults bindings to dynamically skip `HapticManager` calls or directly prevent `PhotoLibraryManager` from pushing raw buffer bytes into the iOS Photos ecosystem. Tactile interactions directly overlay `.heavy` feedback parameters onto the Camera Shutter explicitly complementing `.medium` responses tied to local hardware triggers like the Flash toggle seamlessly bypassing layout thread blocks.

### Privacy & Science
- **Geoprivacy Control (`SettingsGeoprivacyView`)**: Extracted into a dedicated sub-page providing comprehensive user education on coordinate tracking natively. Contains detailed explanations for `Open` (raw sharing for researchers), `Obscured` (50km radius randomized blurring), and `Private` (completely hidden from discovery feed). Modifying selections elegantly cascades a Supabase edge update to the `users` PostgreSQL table immediately in the background via closures. Completely accessible to Ghost Users mapping natively to their anonymous UUID.
- **Export Scans (DwC-A)**: *(Auth Required)* Connects to the `/export-dwca` Deno task through a `Task.detached` thread to pull a `.zip` archive URL back efficiently natively rendering a `ShareLink` payload safely out of memory constraints. Fallback "Sign in with Apple" prompt prevents anonymous users from generating payloads before creating an account.

### Danger Zone & Data Lifecycle
- **Local Cache Management**: Allows dumping `ImageCache.shared` and orphaned `/Caches/` JPG payloads directly off the iPhone flash memory. This directory enumerator is structurally guarded (`!fileURL.lastPathComponent.contains("_temp_upload")`), actively shielding background `OfflineQueueManager` URLSession transfers natively mid-sync to prevent violent network daemon crashes when users manually clear app storage.
- **Account Erasure**: Features a hardline "Delete Account & Data" action executing a native `.destructive` `.confirmationDialog`. This explicitly routes down through the "Danger Zone" Section logically mapping directly beneath the "Sign Out" authentication boundary protecting explicit application layouts continuously. This forces a sequential 4-part wipe: triggering the Deno `/safe-delete` endpoint natively, destroying the GoTrue identity locally (`signOut`), and explicitly dumping the entire device SQLite boundary dynamically (`ScanRepository.shared.purgeAllData`) pushing the user gracefully back into the generic Camera interface smoothly without crashing.

## 6. UI Abstract Modularization
- The UI hierarchy strictly avoids massive structural bindings. The primary navigational routing structure completely avoids UIKit toolbars, abstracting natively from the monolithic `CameraRootView` into an isolated `MainTabBar` capsule component floating 24pts off the bottom horizontal bounds. All core camera utilities (PhotosPicker, Flash Toggle, Hint Banner, Shutter Button) were further explicitly extracted completely entirely out of `CameraRootView.swift` into a dedicated `CameraControlsOverlayView.swift` component structurally decoupling the UI layers from the `NavigationStack` orchestrator completely. Unlike legacy iterations, `CameraControlsOverlayView` inherently abandons global `@EnvironmentObject` managers strictly taking pure intent closures (`onCapture: { viewModel.executeCapture() }`) mapping perfectly into dynamic explicit primitive definitions cleanly.
- `Camera` natively separates layout (`Views/CameraRootView`, `Views/ScanningOverlayView`, `Views/ImageCropperView`), state logic (`ViewModels/CameraViewModel`), and modular sub-views (`Components/ThermalWarningOverlay`, `Components/ViewfinderHintBanner`), completely uncoupling the old monolithic `CameraOverlayComponents` script. Additionally, it structurally shields against "Silent Scan" UI drops: if the user aggressively backgrounds the app during an active AI lookup, `CameraViewModel` explicitly refuses to reset `isAnalyzingFullscreen = false` via an `inferenceEngine.isProcessing` guard, ensuring that upon restoring the app into the foreground, the completed Modal sheet bounds present exactly as expected organically without rendering empty views natively.
- `UserProfileView` natively abstracts completely. The massive scrolling interface natively routes all primary domain bindings deeply into `UserProfileHeaderView` (Avatar metadata, Explorer Persona, nested `UserProfileStatsView` array aggregations, and bottom-anchored Inline Apple/Google Auth routing securely structured underneath contextual gamification bounds). The entire legacy generic `SettingsView` architecture was completely deprecated as a standalone sheet. Huge raw `Section` lists were cleanly decoupled into explicit `ProfilePreferencesSection.swift`, `ProfileExportSection.swift`, `ProfileCommunitySection.swift`, and `ProfileDangerZoneSection.swift` inside `Components/`, leaving `UserProfileView` strictly as the layout orchestrator cleanly.
- The `Scans` feature rigorously enforces Strict Domain-Driven Folders, entirely shattering the monolithic `ScansSearchManager.swift`. The pure array search `.task` logic executes strictly within `ViewModels/ScansSearchManager`, while massive 300+ line SwiftUI declarations (`ScansSearchView`, `ScanSelectionSheetView`, `CollectionDetailView`) inherently live in `Views/`. Foundational models (`Models/SearchableScan`) and discrete Apple UIKit rendering mechanisms natively resolve outside the feature boundary completely mapping directly to global singletons or the overarching `Core/UI/` component directory universally. Check `docs/features-and-hardware/components-guide.md` for explicit global interface primitives (`EmptyStateView`, `ArchivedVisualsView`, `ScanDeletionDialogModifier`).
